## Why

To support seamless installation across environments (pip, pipx, Homebrew) and protect users and maintainers, `slash-agent` needs a standardized shell initialization mechanism (`slash-agent init <shell>`) across supported shells (Bash, Zsh, Ksh, Fish) and explicit, user-friendly safety and cost guidance in documentation.

## What Changes

- Add a `slash-agent init [shell]` CLI subcommand that outputs shell integration wrapper functions for `bash`, `zsh`, `ksh`, and `fish` to stdout (auto-detecting the active shell if omitted).
- Support an `--install` flag in `slash-agent init` that reuses the profile registration logic from `installer.sh` to idempotently write to the appropriate shell RC file (`~/.zshrc`, `~/.config/fish/config.fish`, `~/.kshrc`, `~/.bashrc`, `~/.bash_profile`).
- Support `--cmd <name>` option in `init` to allow customizing the shell alias/function name (defaults to `/agent` and `agent`).
- Support `--update` / `--upgrade` (`-u`) flag in `/agent` and `slash-agent` to easily update the installation (running `installer.sh` in git environments or pip upgrade in package environments).
- Reorganize `README.md` so the **Quick Start (5-Second Install)** section appears immediately below the AI pairing tip and right above the 10-Second Reality Check.
- Add a prominent, non-intrusive **Best Practices, Safety & Cost Notice** section to `README.md` and `docs/` clarifying token spend responsibility, interactive review best practices, and unattended execution risks.
- Add standard packaging metadata (`pyproject.toml`) with console script entry point for `slash-agent`.

## Capabilities

### Modified Capabilities
- `shell-agent`: Add `init` CLI subcommand to generate shell integration hooks dynamically for Bash, Zsh, Ksh, and Fish without hardcoded virtualenv paths.

## Impact

- CLI entrypoint in `slash_agent/main.py`: handles `init` command before standard prompt parsing.
- Shell integrations in `bin/`: align with output generated by `init`.
- Documentation in `README.md` and `docs/documentation.md`.
- `pyproject.toml`: build configuration and console entry point.
